# Profile Manager

## Status

Planned

## Priority

High

## Goal

Provide the primary operational abstraction within Bisync Hub.

A Profile represents a managed synchronization workload built on top of one or more Rclone remotes.

The Profile Manager allows users to create, configure, organize, monitor, and operate synchronization workloads without needing to interact directly with Rclone configuration details.

Profiles become the central object used throughout the platform.

All major Bisync Hub functionality operates against Profiles.

Examples:

- OAuth Connection Manager validates Profiles
- Synchronization Orchestrator executes Profiles
- Interactive Sync Review reviews Profile operations
- Notifications are generated by Profiles
- Diagnostics evaluate Profile health

---

# Design Philosophy

## Profiles Are Operational Objects

Rclone remotes define connectivity.

Profiles define operations.

Example:

```text
Rclone Remote:

gdrive
```

defines:

```text
How to connect to Google Drive
```

Profile:

```text
Personal Google Drive
```

defines:

```text
What to synchronize

When to synchronize

How to synchronize

How to handle conflicts

How to notify users
```

# Ownership Model

The platform is intentionally divided between Rclone-owned configuration and Bisync Hub-owned operational behavior.

This separation prevents configuration drift and ensures that Rclone remains the authoritative source of truth for backend configuration.

---

## Rclone Owns

The following data is owned exclusively by Rclone.

Examples:

```text
Remote Definitions

Backend Type

Authentication Configuration

Client ID

Client Secret

OAuth Tokens

Refresh Tokens

Provider-Specific Settings

Remote Connectivity Details
```

Bisync Hub must never become a second source of truth for these values.

Remote configuration changes are always performed through the Rclone RC Framework.

---

## Profile Manager Owns

The Profile Manager owns operational settings.

Examples:

```text
Schedule

Review Mode

Notification Preferences

Delete Thresholds

Canary Validation

Profile Metadata

Operational State

Execution History
```

These settings do not exist in Rclone and are persisted by Bisync Hub.

---

## Source Of Truth

```text
Remote Configuration
    ↓
    Rclone

Operational Configuration
    ↓
    Profile Manager
```

This separation is mandatory.

---

## Rclone Remotes Are External Dependencies

Bisync Hub does not own remotes.

Rclone remains the source of truth.

Profiles reference remotes.

---

## Profiles Are First-Class Citizens

The Profile is the primary object users interact with.

Users think in:

```text
Personal Backup

Work Documents

Photo Archive
```

not:

```text
drive:

onedrive:

dropbox:
```

## Excluded

Remote configuration changes are not versioned by the Profile Manager.

Examples:

```text

Client Secret

OAuth Settings

Backend Configuration
```

These remain owned by Rclone.

The Profile Manager records that a remote configuration change occurred but does not maintain a copy of the configuration itself.

# Success Criteria

A Profile is an operational wrapper around an Rclone Remote.

Rclone remains the authoritative source of truth for:

- Backend Configuration
- Authentication Configuration
- Remote Definitions

The Profile Manager remains the authoritative source of truth for:

- Operational Behavior
- Scheduling
- Review Policies
- Notifications
- Safety Controls

All remote configuration changes flow through the Rclone RC Framework.

The Profile Manager never directly edits rclone.conf and never becomes a duplicate configuration system.
